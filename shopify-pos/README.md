# Defy Shopify POS extensions

This isolated package contains Pokémon Sealed, Defy Pricing, and the existing
Defy Receiving extension. Dependencies and its lockfile are independent of the
Next.js app. The root app excludes this directory from its React typechecking
and lint configuration because Shopify POS uses Preact and Polaris web
components.

## Pokémon sealed price checker

Open **Pokémon Sealed** and scan the manufacturer barcode or enter its SKU.
Known matches retrieve a fresh Scrydex USD market price. For a new code, search
by name, review the exact English package, and confirm its match once. The
match is shared across POS devices using this app installation.

Use **Refresh price**, **Change matched product**, or **Next product** as needed.
Checking does not change Shopify prices, stock, or the cart. Every quote bypasses
the catalog cache. See [setup, limits, and release](../docs/SHOPIFY_POS_SEALED_PRICING.md).

## Defy Pricing workflow

1. In Shopify POS, open the **Defy Pricing** smart-grid tile.
2. Scan the SKU/barcode with the connected scanner, use **Scan with camera**, or
   enter the SKU and choose **Look up price**.
3. The backend matches the Shopify variant and its card identity, gets a Scrydex
   quote, and updates its Shopify catalog price. The modal shows the customer
   selling price, with the Riftbound singles rule calculated on the server.
4. Choose **Add to cart**. The extension checks that POS has received the price,
   adds the actual inventory-linked variant, and verifies the cart unit price.

The scanner is active inside this modal. Scanning in Shopify's regular search
or cart does not trigger Defy Pricing. A failed lookup adds nothing. If POS is
still syncing the catalog price after the bounded check, retry the lookup after
sync completes. Products must be available on the Point of Sale sales channel.

The same variant cannot be added a second time through the pricing modal.
Change its quantity in the cart instead. If the new cart line has an unexpected
price, the extension removes only a newly created line carrying that operation's
marker. If Shopify cannot confirm removal, staff must check the cart before
checkout. Existing cart lines are never removed by this workflow.

Only USD POS locations are supported. Regular Shopify discounts and taxes still
apply at checkout. No custom-sale items or cart price overrides are used.

## Backend and credentials

The extension posts `{ "code": "the-scanned-sku" }` to
`https://defy-store-os.vercel.app/api/shopify/pos/pricing` with a freshly issued
Shopify session token. API keys and Shopify Admin credentials stay on the
backend. A POS account with permission to use the installed app is required;
the extension displays an error if it cannot obtain a token.

The backend's Shopify client ID/secret must belong to the Shopify app that owns
this extension. It verifies tokens and restricts requests to the configured
store. Changing the backend host requires a source change and extension
release. No `NEXT_PUBLIC_` key or secret belongs in this package.

## Validation

```sh
cd shopify-pos
npm ci
npm test
```

Tests cover authentication, currency restrictions, stale prices, duplicate scans
and cart additions, ambiguous lookups, and safe rollback. The package typechecks
all extension sources and bundles every configured target with a 64 KiB size
limit. `dist/` is ignored and is only a local verification output.

CLI app build/deployment must run against the existing app linked in
`shopify.app.toml`, preserving **all three** extensions. When registering a new
extension, keep the UID generated by Shopify CLI in its extension TOML.
Do not replace the existing Receiving UID. Deploying the Next.js backend does
not publish these Shopify extensions.

After installation/release, add **Defy Pricing** in the POS smart-grid editor.
Before using the feature at the counter, verify a real scan in the Shopify POS
app and confirm cart price, quantity, tax, and inventory behavior on a
development store. Unit tests and a browser do not emulate the native POS host.
